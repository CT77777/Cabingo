# Cabingo v0.4.1 · 音量、說明與失焦暫停

- 喇叭與滑桿整合為同一組控制，深藍底、薄荷綠線條及圓角沿用現有 UI；Cabingo 品牌標誌保留。
- 喇叭靜音後滑桿顯示 0，取消靜音恢復前次音量；拖曳到 0 靜音，調高即取消靜音。音量與前次非零音量儲存在本機。
- 操作說明改由 ⓘ 展開，閱讀期間暫停，預設不再顯示長篇規則。
- window blur／document hidden 顯示全畫面遮罩，凍結時間、處理與音訊；回到視窗不自行恢復。點擊繼續、Enter、空白鍵或 Escape 可返回。
- 保留原有判斷、首次說明與處理步驟；離開前若已手動暫停，先回到原暫停畫面。
- 遮罩使用 modal 語意、背景 inert、Tab 焦點限制。繼續鍵的重複與放開事件會阻止瀏覽器預設行為，避免誤關閉下一張面板；若按鍵已在視窗外放開，新的非重複按鍵可正常操作。

## 驗證

81 項規則與 56 項正式控制器測試通過；Three.js 場景、動作、事件、音訊與評級測試通過。靜態版面增加全視窗遮罩、modal 層級與音量群組檢查，共 303 項。建置與差異空白檢查通過。

Chrome 實際檢查桌面介面、按 ⓘ 展開／收合、滑桿歸零與恢復、SVG 靜音與聲波顯示切換，以及 320×568 手機的控制列。失焦與鍵盤恢復流程使用真實控制器的模擬 DOM／事件測試；受瀏覽器自動化焦點模擬影響，這輪沒有宣稱完成原生視窗切換的端到端驗證。Safari／Firefox 的原生 Space 預設事件與 Safari display:contents 的 inert 行為尚未手動檢查。

## Claude Code review

實際 Claude Code CLI 唯讀審查。首輪指出繼續鍵重複造成面板誤觸，以及 SVG path 的 hidden 屬性不會跟隨 HTML hidden property。兩項均先重現、加入回歸測試後修正。複查確認 blocking findings 全部修復；之後也處理了視窗外放開按鍵與手機按鈕 accessible name 的建議，最後一輪審查再次判定 ready to push。測試由實作者執行，Claude 未啟動瀏覽器。
