# Cabingo v0.4 原創配樂與操作式處理

頁籤與畫面品牌標題統一為 Cabingo。

本輪依使用者需求與 cabin-please-3D-v0.3.1-review.md 調整：

- 原創八小節 lounge 鋼琴循環配樂；暫停選單可獨立調整音樂音量，閱讀時降低音樂，暫停／失焦停止。
- 網頁預設啟用操作式處理：點按、按住到綠區後放開，以完成步驟代替被動等候。操作失敗可重試，不扣判斷分。鍵盤 E 與螢幕互動按鈕皆可操作。
- 行李抬起收妥、安全帶確認、咖啡與餐桌、水杯、毯子、交接與走道引導各有步驟；正式 100 秒、交接後同事送達 12 秒、選錯 2 秒回饋保留。
- 每題保留一個幽默選項，另有兩個依現場線索選擇的正式回應；服務幽默選項仍可能合理，沒有用語氣洩漏答案。
- 近景統一切入方向；頭頂櫃縮小，近景置物櫃與前方旅客淡出。座椅仍使用靜態批次幾何，沒有逐張椅背淡出。
- 標籤依旅客頭部實際世界座標定位；機艙左右以旅客面向表示，走道事件沿用原旅客位置。回報標籤只在前方附近顯示。
- 手機分數列縮成一行，直向巡艙畫面往下移，保留後段需求的視野。
- 練習、未完成與 0 星結果不寫入最佳紀錄，舊的 0 星紀錄會忽略。

## 驗證

- npm run test:all：81 項既有規則、48 項控制器測試、Three.js 場景與投影、事件／演出／音訊／評級測試通過；靜態版面 300/300 通過。
- 新增操作模式覆蓋六個任務的 18 種變體、早放／晚放重試、暫停取消按住、交接送達。正式控制器完整路線以 handsOn:true 執行，完成六項與回報，零失誤。
- 保留純規則 API 的舊計時模式（createState 預設 handsOn:false）作相容回歸；正式網頁及重新開始皆明確啟用 handsOn:true。
- 實際 Chrome 檢查桌面 1512×900 三欄選項、手機 390×844 直排選項與單行分數，操作 E 按住放開完成行李，以及點按互動推進確認步驟。音樂滑桿可獨立調整。
- 建置與差異空白檢查通過。聲音樣本為有限、非零且不截幅的原創 PCM 循環；生命週期使用 AudioContext 替身測試。

尚未完成真人五人首輪完成率、真實手機 CPU 降速、完整主觀聽感評估；因此不調整 100 秒時限、不沿用舊版 fps 結果，也不宣稱具備真實錄音音效或 3A 品質。

## Claude Code

依使用者要求，實際以 Claude Code 2.1.300 CLI 進行三輪唯讀推送前審查，結論皆為 Ready to push，並依發現補正：首次說明取消按住、透明材質重編譯、每幀更新操作量表、成功音效等待接受操作後才觸發、觸控指標在面板切換時釋放、音樂失敗保留音效、材質回收與行李尺寸。

控制器測試預設已改為網頁實際使用的 handsOn:true。最後依 Claude 建議，把幽默文字綁在操作 ID、以種子選擇哪個選項套用，避免幽默位置或措辭暗示對錯；測試涵蓋 40 種種子與全部安全變體。同時將指標變數移到頂部宣告。

測試由實作者執行，Claude 檢查提供的差異與來源，沒有實際啟動遊戲。實際 Chrome 已確認左側桌面行李題、手機近景與透明效果。
