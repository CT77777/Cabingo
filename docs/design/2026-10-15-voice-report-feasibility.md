# Cabingo 語音回報與 AI：技術可行性

2026-10-15｜已查閱官方資料，並透過實際 Claude Code CLI 進行兩輪設計討論。尚未實作語音、下載模型或測試辨識準確率。

## 結論

可以加入語音回報。但目前不能保證「繁體中文、所有手機、完全本機、免費且立即可用」同時成立。建議先建立可編輯文字回報，再逐步加入可用的語音輸入與 AI 解析。

回報應由三個部分組成：語音轉文字、解析玩家宣稱、對照本輪遊戲紀錄。模型負責協助理解口語，程式負責核對事實。正式巡艙是否完成，由遊戲紀錄決定。

## 技術選項

| 方案 | 純客戶端 | 費用與主要限制 | 建議用途 |
| --- | --- | --- | --- |
| 文字輸入＋規則核對 | 是 | 不產生 AI 推論帳單；規則無法可靠理解所有自由口語 | 第一階段。顯示解析出的項目，允許玩家確認與修正。標示「規則檢核」，不冒稱 AI。 |
| 瀏覽器本機語音辨識 | 支援時可以 | 需偵測本機辨識及繁中語言包；不同裝置不能一概保證 | 有支援才提供，下載語言包前取得玩家同意。 |
| 瀏覽器一般語音辨識 | 不保證 | 瀏覽器可能傳送音訊到遠端服務；不能當成永久免費、有固定配額或 SLA 的服務 | 明確標示為線上辨識，玩家主動選用；不支援就保留文字。 |
| 自行載入多語 Whisper | 可在本機推論 | 首次需下載模型，耗用記憶體與運算；手機與 3D 同時運行的效能待實測 | 第二階段實驗。中文使用多語模型，不能誤用僅英文的 `.en` 模型。 |
| WebLLM 小型語言模型 | 可在本機推論 | 需 WebGPU、下載與快取模型；繁中解析品質、延遲和記憶體待測 | 選用的 AI 宣稱解析，不列為通用手機必備功能。 |
| Chrome Prompt API | 符合條件時可本機推論 | 官方目前列出的語言不含中文，Android／iOS 不支援，亦有桌機硬體條件 | 目前不作 Cabingo 繁中回報的主要方案。 |
| Cloudflare Workers AI | 否 | 目前每日免費 10,000 Neurons，為帳號共用額度；Free 超額會失敗，部分模型另需付費方案 | 若日後接受小型後端，可評估。沒有選定模型與每次用量前，不換算成固定每日人數。 |

官方依據：[MDN 本機語音辨識](https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognition/processLocally)、[Web Speech 使用說明](https://developer.mozilla.org/en-US/docs/Web/API/Web_Speech_API/Using_the_Web_Speech_API)、[Transformers.js WebGPU](https://huggingface.co/docs/transformers.js/guides/webgpu)、[WebLLM](https://webllm.mlc.ai/docs/user/get_started.html)、[Chrome Prompt API](https://developer.chrome.com/docs/ai/prompt-api)、[Workers AI 定價](https://developers.cloudflare.com/workers-ai/platform/pricing/)。查核日期為 2026-10-15，正式實作時需再次核對支援與價格。

「本機推論」表示辨識或解析不需把回報送到推論伺服器，首次取得模型仍可能需要網路與下載流量。雲端方案的憑證不可放進公開前端；如採 Workers AI，使用 Worker 的伺服器端綁定並控制用量。

## 建議操作流程

1. 玩家完成巡艙，走回前方按 E。這段移動仍計入行動時間。
2. 遊戲確定完成後固定本輪紀錄與行動時間，進入獨立的回報講評。
3. 玩家可打字；有支援的裝置也可選語音。錄音前顯示本機或線上模式，錄音期間停止遊戲音樂與音效。
4. 顯示可編輯逐字稿。玩家可重錄、修正、取消或略過回報。
5. AI 若可用，抽取「回報項目、宣稱狀態、原文引用」。程式驗證輸出格式與引用，再對照固定的遊戲紀錄。
6. 講評分為「正確提及、漏報、與紀錄矛盾、需要確認」。解析不確定或模型失敗時允許玩家確認，不因技術故障判定巡艙失敗。

僅檢查引用存在，仍不能保證理解正確；否定、數量、主詞與「全部」所指的範圍都要另外處理。回報文字視為待解析資料，不當成模型的操作指令。

## 判斷範例

| 真實紀錄 | 玩家說法 | 應有回饋 |
| --- | --- | --- |
| 工作均完成，其中一件由同事完成 | 全部完成 | 完成狀態正確；若講評要求回報交接，列出漏報交接。 |
| 工作均完成，其中一件由同事完成 | 全部是我親自完成 | 與交接紀錄矛盾。 |
| 旅客曾等候逾時，後續已處理完成 | 全部完成 | 完成狀態正確；延誤屬過程資訊，不可直接判為虛假。 |
| 旅客曾等候逾時 | 沒有任何延誤 | 與延誤紀錄矛盾。 |
| 仍有未處理走道事件 | 本輪所有工作都完成 | 與未結事件矛盾；目前正式回報入口仍應由遊戲阻止提前完成。 |
| 否定或範圍無法可靠解析 | 不是全部都由我處理 | 請玩家確認，不自動推成「全部由我完成」。 |

以上對「完成」與「過程漏報」的區分，是兩輪 Claude 討論後修正的重點。交接不等於未完成，曾經延誤也不等於當下仍未完成。

## 實作順序與驗證

先做文字報告、結構化紀錄及可確認的核對結果。接著加入可用性偵測與選用語音，最後評估本機 Whisper／小型 LLM。這個順序能先驗證回報是否有趣，以及講評是否公平。

測試至少涵蓋繁中否定、數量、同義詞、交接、延誤、補救、空泛「全部完成」、逐字稿誤字、靜音與噪音；並涵蓋麥克風拒絕、模型下載中斷、離線、記憶體不足、重新錄音及取消。手機 Safari／Chrome 與桌機各瀏覽器分別實測。

目前尚無裝置實測數據，因此不承諾辨識準確率、即時速度、模型下載大小或每日可服務人數。語音回報功能尚未加入目前版本。
