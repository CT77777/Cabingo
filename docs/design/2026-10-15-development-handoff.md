### 必須延續的行為

- 產品名稱為 **Cabingo**。沿用現有深藍、薄荷綠與金色；Logo、音量、暫停遮罩與說明入口維持一致。
- 鍵盤主互動為 **空白鍵**，觸控使用互動鈕；移動方向對齊畫面。舊文件提到 E 是歷史操作。
- 選好一般任務後直接演出，不要求反覆確認或重複點按。走道回座則需要實際移動，站著等不會完成正常引導。
- 同事送達才算任務完成。安排等候、清完走道不代表服務已完成；不可提前開放回報。
- 成功正式通關且至少 1 星，並完成對應任務才領卡。練習、逾時、零星與僅看對話不發卡；同事已完成任務可領卡，登機教學任務須等整章正式成功才領卡。
- 結算只顯示本次新卡；既有卡保留、共用卡不重發。卡面已依使用者要求移除「知識草稿 · 待專業審閱」；`reviewed:false` 與展開解說的審閱狀態仍保留，不代表專業認證。
- 暫停、失焦、教學與閱讀應凍結對應遊戲時間及聲音；失焦後必須由玩家繼續。收藏冊、教學與恢復視窗保留鍵盤焦點及長按保護。

| --- | --- |

| `public/boarding.mjs` | 教學、人流與登機事件 |

| `public/assets/cards/` | 8 張原創本機 SVG，必須隨建置交付 |
| `public/main.js` | 輸入、DOM、焦點、localStorage、音效事件與迴圈 |
| `public/presentation.mjs`、`public/scene.js` | 純演出計算與 Three.js 繪製；不自行修改規則 |
| `public/audio.mjs`、`public/results.mjs` | 聲音與評級 |

現行鍵：`cabin3d-audio-v1`、`cabin3d-best-v1`、`cabin3d-lessons-v2`、`cabin3d-campaign-v2`、`cabin3d-codex-v1`。campaign v1 與舊最佳紀錄有匯入相容，未來格式不得覆寫。收藏冊保留同格式未知卡 ID，計數只計已知卡。localStorage 依來源分開；`localhost` 和 `127.0.0.1` 的航班、收藏、紀錄與音量各自獨立，所有存檔驗收都須記錄來源。

新玩家入口由 `createCampaign()` 設為 `boarding`；`DEFAULT_CHAPTER_ID` 仍是舊 API 的 `preflight` 預設。新增入口需讀 campaign，不要用此常數取代進度政策。

## 開工與交付

1. 查閱本文件、roadmap、相關設計及驗收；確認工作區與最新 PR 狀態，保留其他工作。
2. 從最新 main 建獨立分支，同一代理依序實作。不要直接推 main，也不要自行合併待審功能。
3. Node.js 20 以上；`npm start` 開本機預覽，`npm run test:all` 跑規則與靜態版面，`npm run build` 輸出 `dist/`。版面測試先建立 Python 環境並執行 `python -m pip install -r requirements-dev.txt`（固定 `lxml` 版本），詳見 [README](../../README.md)。
4. 新增實際有意義的回歸；桌面 1194×959、手機 390×844 與短螢幕確認可讀可操作，檢查主控台。
5. 寫 `docs/validation/`，區分自動測試、瀏覽器尺寸模擬、實機與專業審閱。推送前用實際 Claude Code CLI review，處理發現後再發 PR。
6. 依 README，Cloudflare Git 整合監聽 main；設定在 Dashboard，倉庫沒有 GitHub Actions 部署 workflow。本機成功不等於部署成功，正式網址與部署結果以對應 commit 的 Workers Builds／Dashboard 為準。
