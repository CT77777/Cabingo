# Cabingo：從選答案走向機艙工作

2026-10-15｜玩法提案，尚未實作或驗證平衡

## 問題

目前的點按、按住與放開，主要發生在玩家選擇處理方案之後。玩家仍依照指定步驟完成動作，無法決定拿取的物件、放置位置或服務批次。增加更多按鍵步驟，未必增加遊戲深度。

新的操作應讓玩家決定「拿什麼、放哪裡、先處理誰」。選項保留給溝通、資訊判斷和同事交接。

已使用實際 Claude Code CLI 討論此方案。它指出：可任意交換順序、但沒有不同代價的整理，仍可能只是確認步驟。建議先做物件整理與服務取物，兩者共用兩格攜帶空間；行李容量拼放延後。這是根據提供的程式現況與官方資料進行的設計諮詢，Claude 沒有操作或測試遊戲。

## 第一段可玩的內容

建議先驗證兩種共用拿取／放置操作的玩法，再擴展全章。新操作先放入不計時練習，正式模式的時限另行試玩調整。

### 物件整理

玩家直接操作杯子、書本與餐桌。杯子和書本的處理先後可以不同；只有桌面仍有物件時，餐桌才無法折起。嘗試折桌會看到阻擋物件的提示，物件不消失，也不直接扣安全分。

單一餐桌的整理主要提供操作手感。它必須與攜帶容量、相鄰旅客需求或下一個目的地產生關係，才會形成有意義的選擇；不能把固定三步流程包裝成自由玩法。

可先驗證「自己收空杯，佔一格攜帶空間」與「請清醒旅客自行整理，自己繼續送水」的差別。旅客物品由旅客收妥，不直接搬動私人物品。背景動作應讓玩家繼續工作，避免再變成原地看進度條。

### 取物與服務安排

托盤先設兩格。玩家在補給點拿水或毯子，再親自送到旅客手中。需求、手上物品與可放置位置都在場景中清楚顯示。

例如兩名旅客要水、另一名旅客要毯子。玩家可以帶兩杯水一次完成同類需求，也可以帶水和毯子，優先照顧較急的旅客；一次交接則可分擔較遠的需求。這些安排必須在步行距離和旅客反應上出現差異。

拿錯物品可以放回。送錯對象時，旅客示意所需物品，物品仍留在托盤，玩家可以更正。第一版不增加物品價格、永久升級或複雜背包。

## 幽默與文字

「餐桌今天還想加班嗎？」沒有說明動作，也缺少可見的笑點。動作文字改用具體說法，例如「請把空餐桌收起」「幫忙安置咖啡和物品」「查看收妥的餐桌」。

幽默放在旅客的表情、物件和完成後的短句。不要要求每一道題固定有一個笑話，也不要讓幽默暗示正確答案。旅客反應必須符合當下物件狀態。

## 驗收方式

1. 玩家能以不同順序完成同一段需求；系統不強制唯一劇本。
2. 物品確實從原位置移到手上，再到目的地，暫停與恢復後位置一致。
3. 至少兩種服務安排可成功，且步行距離或旅客等待結果不同。
4. 拿錯、放錯或操作順序不當都有清楚、可逆的補救方式。
5. 鍵盤和觸控都能完成；例行整理與交付不必先回答三選一。

尚未驗證：這兩種玩法是否足夠有趣、托盤兩格是否合適，以及正式模式應使用多少時間。這些問題要以可玩版本測試，不能從參考作品直接推定。
