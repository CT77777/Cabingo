## 二、已確認的決策（不要自行推翻）

1. **定位**：遊戲體驗為主，結合航空知識，讓準備**台灣航空公司**空服員招考的玩家邊玩邊學。
2. **國籍航空通用版**：不依個別航空公司區分內容。
3. **語言只做華語、英文、台語**。不加日文、韓文。
4. **主線依航班時間順序**：登機 → 起飛前巡艙 → 滑行起飛 → 餐飲服務 → 亂流 → 夜航 → 下降前準備 → 不平靜的落地 → 尾聲下機。
5. **登機是第 1 章，兼教學關**。現有「起飛前巡艙」改為第 2 章，介面與資料要改號。
6. **「不舒服的旅客」「衝突與情緒」不是固定章節**，而是隨機事件。
7. **隨機事件依玩家表現值決定難度**，表現越好，事件越難。
8. **緊急情境**（心肺復甦、死亡處理、客艙失壓、緊急撤離、水上迫降、機上保安威脅）納入隨機事件第二、三級。
9. **保安威脅只做通用原則**：不指涉真實事件，不呈現具體保安程序與戰術，不呈現血腥畫面。
10. **高強度情境預設關閉**：由玩家在設定中開啟；表現好時邀請開啟，但不強制。
11. **免責聲明改寫**為「簡化的學習內容，實際程序以各航空公司訓練為準」。

- 建立章節註冊表，例如 `public/chapters/index.mjs`。每章定義：`id`、`order`、`title`、`phase`（航班階段）、`duration`、任務定義、教學與首次說明清單、可插入的隨機事件階段。
- 把現有起飛前巡艙抽成 `chapter id: 'preflight'`、`order: 2`。規則行為不變，既有 81 項規則測試必須全過。
- 新增**航班進度狀態**（campaign）：目前章節、各章最佳星等、已解鎖章節。新 localStorage 鍵 `cabin3d-campaign-v1`。
- 新增**跨章記憶**：以固定角色 ID 記錄互動結果，例如 `{ elder: { helped: true, mistakes: 0 } }`。M0 只建資料結構與測試，先不使用。
- 開始選單加上章節選擇；未解鎖章節顯示鎖頭。
- 介面中「PRE-FLIGHT / 01」等編號改由章節資料產生。

**驗收**
- 現有關卡改為第 2 章後，玩法、計時、評分與接手基準 v0.4.6 完全一致（以既有測試證明）；不恢復 v0.4.4 的舊式操作。
- 新增章節框架測試：章節排序、解鎖、紀錄讀寫，以及損壞或舊版資料的容錯。

### M1：第 1 章「登機」（兼教學關）

**新機制**
- **會走動的旅客**：從前門進入，沿走道走到座位坐下。走動中會阻擋玩家，阻擋判定沿用 `canStand` 的方式。
- **走道擁擠值**：同時站在走道的人數超過門檻並持續一段時間，記一次安全事件。
- **座位糾紛**：整章最多 1 件。兩位旅客持同一座位號，其中一人看錯登機證。近景時把登機證做成可見的線索。

**教學段**：前 30 秒不計時，分 4 步，一次教一件事：走路靠近 → 按 E 進近景 → 看線索選擇（行李放不進頭頂櫃）→ 紅色與綠色標記的差別。每步完成才出現下一步。

**數值初稿**：90 秒（教學段不計）、同時需求上限 3、平均耐心 40 秒、不可交接。

**角色延續**：至少讓一位固定角色（例如第一次搭機的長輩）在第 1、2 章都出現，並寫入跨章記憶。

**驗收**
- 新玩家不看說明也能完成教學段。
- 旅客走動在暫停與失焦時凍結，恢復後位置一致。
- 鍵盤與觸控都能完成；減少動態效果設定下旅客仍能到位（可改成瞬移或淡入）。
- 規則測試覆蓋：旅客路徑、擁擠計算、座位糾紛的各種變體。

### M2：學習層第一版

- **知識卡資料**：建立 `public/knowledge/` 資料檔，每張卡包含 `id`、`category`、`title`、`body`（2～3 句）、`sources`（陣列，至少一筆）、`reviewed`（布林，預設 false）、`chapters`。
- **結算的「為什麼」**：章節結算列出本局判斷，每題附對應知識卡摘要；答錯的排最前面。可展開或收合，預設收合不打斷。
- **知識圖鑑**：玩過的內容解鎖對應卡片；從開始選單進入。進度存在 `cabin3d-codex-v1`。
- **第一批內容**：先為第 1、2 章所有情境寫知識卡。`reviewed:false` 的卡片在介面標示「待專業審閱」。

**驗收**：每個判斷題都對應到至少一張知識卡（用測試檢查對應完整性）；沒有任何卡片缺少 `sources`。

### M3：第 3 章「滑行與起飛」、第 4 章「巡航餐飲服務」

- **第 3 章**：安全帶燈（劇本控制）、組員座位（坐下後不能走動）、廣播（坐著也能提醒全艙，但效果較弱）。60 秒。核心抉擇是「冒險去處理，還是坐下用廣播」。
- **第 4 章**：採用 `gameplay-direction.md` 的托盤兩格與取物、放置操作。餐車佔滿走道、只能前後移動；餐點種類數量有限；過敏資訊一半在旅客名單、一半要近景觀察；同事從另一端推車。
- **劇本事件系統**：依時間或條件觸發燈號、廣播、狀態變化。第 3 章就需要，之後各章共用。

### M4：第 5 章「亂流」

- 機艙晃動（鏡頭與角色，減少動態效果時改用畫面邊緣提示）、移動變慢與偏移、兩段亂流（第二段時間點用種子隨機，只提前 5 秒提示）、熱飲潑灑成為新的安全事件。
- 可參考 2D 版第二章的亂流流程，但改成實際在 3D 中發生。

**到 M4 為止（第 1～5 章）先停下**，做一次完整的真人測試：記錄每章第一次通關率，目標第 1～3 章 80%、第 4～5 章 60%。依結果調整數值後，再進入 M5。

### M5：表現值與隨機事件

- **表現值**：依最近 3 局計算 0～100（星等 40%、安全失誤 30%、剩餘時間比例 15%、旅客感受 15%），存在 `cabin3d-skill-v1`。權重為初稿。
- **等級**：見習 0～39、正式組員 40～69、資深組員 70～100。
- **抽選規則**：依等級與航班階段抽事件；同一事件不連續出現；第三級失敗後下一局最多第二級；插入事件時章節時限延長事件長度。
- **第一級事件**先做：輕微不適、座位與扶手糾紛、要求換位或升等。需要多輪對話系統（2～3 輪，有情緒值）。
- **第二級事件**：心肺復甦（節奏小遊戲）、客艙失壓（自己先戴面罩）、酒醉旅客、洗手間冒煙。
- **高強度情境開關**：設定中提供，預設關閉。進入事件前顯示內容提醒，可跳過。

### M6：學習模式擴充

廣播練習（華語、英文、台語，附台羅拼音，可錄音對照）、面試情境題模式（重用遊戲情境，提供答題思路而非標準答案）、免稅品心算小遊戲（接在第 4 章後）、錯題本、英文旅客與全英文模式。

### 之後

第 6～8 章、尾聲、第三級事件（緊急撤離、水上迫降、保安威脅）。撤離需要艙門、滑梯、機外場景，製作量最大；保安威脅需要最謹慎的審閱。

## 六、注意事項

- **規則與演出分離**：新規則放在純函式模組並寫 Node 測試；Three.js 只讀狀態。延續 `preflight.mjs` 與 `presentation.mjs` 的分工。
- **決定性**：所有隨機都走種子亂數，測試才能重現。
- **不要未經測試就改平衡**：現有 100 秒等數值是否合適，尚未經真人驗證。v0.4 的驗證紀錄也明確說「不調整 100 秒時限」。
- **既有流程**：每版寫 `docs/validation/`；推送前依專案慣例做 Claude Code 唯讀審查；Cloudflare 監聽 main 自動部署，請在分支開發。
- **內容正確性**：急救、失壓、撤離相關知識卡與流程，上線前要請專業顧問審閱；未審閱前保持 `reviewed:false` 並在介面標示。CPR 節奏採公開的民眾急救指引（例如每分鐘 100～120 下），撤離目標 90 秒來自航空器認證時的撤離標準。
- **保安情境**：只做察覺、冷靜、隱密通報、保護旅客、聽從指示。不寫具體程序。
- **不使用真實名稱**：不使用真實航空公司名稱、航班號、真實廣播稿或真實事件。
- **效能**：v0.4 起未重新量測 fps。加入走動旅客與晃動後，需要在手機與 CPU 降速下重新量測。
