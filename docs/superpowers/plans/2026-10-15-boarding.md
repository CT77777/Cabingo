# Cabingo M1 Boarding Implementation Plan

> Execute sequentially with superpowers:executing-plans. User selected the same agent; actual Claude Code review before push, separate PR only.

**Goal:** Playable chapter1 boarding with an interactive tutorial, passenger traffic, one evidence-based seat dispute and persistent elder continuity.
**Architecture:** Add pure boarding rules and chapter data beside the existing preflight engine. Reuse input, contextual actions, scoring, pause and scene while deriving task totals and capability copy from chapter metadata. Version2 campaign preserves M0 access but starts new players in boarding.
**Tech Stack:** Existing Three.js / vanilla ES modules / Node and Python tests; no external dependencies.
**Spec:** docs/design/2026-10-15-handoff-codex-roadmap.md M1 and chapter-and-event-design.md chapter1.

## Global constraints

- Formal boarding90 seconds, no handoff, at most3 active demands, patience40 seconds.
- Interactive tutorial about30 seconds untimed; steps advance through deliberate gameplay, no mandatory idle waiting. Formal clock starts only after tutorial.
- Passenger movement and congestion freeze during dialog, lesson, manual/focus pause and results. Reduced motion keeps necessary travel but removes gait/bob.
- Existing preflight API and81 rules remain compatible. Default createState remains preflight for callers; new campaign entry is boarding.
- New save cabin3d-campaign-v2; migrate v1/legacy best without treating bridge unlock as completed boarding. Preserve existing preflight access. Unknown future versions must not be overwritten.
- One elder character has a consistent appearance and continuity copy in both chapters; no speech/model network requests.
- PR targets main without merge; no direct main push.

## Review focus

- Walking actor cannot trap a player or overlap queues; path completes without player teleportation. Test collisions and paused snapshots.
- Seat dispute has3 deterministic variants and exactly one correct evidence interpretation; wrong choices retain safe retry, no task credit.
- Tutorial never expires90-second clock or accumulates penalty, including close/reopen and practice.
- Storage denial, concurrent result writes and future version data preserve play and progress.
- Narrow UI keeps clues, choices and tutorial status readable; same keyboard/touch affordances as preflight.
