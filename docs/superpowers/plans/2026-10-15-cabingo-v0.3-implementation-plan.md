# Cabingo v0.3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 讓第一章透過聲音、人物與處理動畫、近景、頭頂圖示及結算回饋更有生命感。

**Architecture:** 規則層繼續決定任務、碰撞、處理進度與分數，透過有序事件通知演出層。純函式管理姿態、標籤配置與評級；場景與音訊各自消費事件，控制器負責介面與生命週期。

**Tech Stack:** Node.js >=20、原生 ES modules、既有 Three.js 0.180.0、Web Audio、Python >=3.10 與 lxml 6.1.1。

**Spec:** `docs/superpowers/specs/2026-10-15-cabingo-v0.3-design.md`（使用者於 2026-10-15 確認）。

## Global Constraints

- 正式模式維持 100 秒；練習模式維持不計時、不扣分。
- 一章、三項安全檢查、三個服務需求、一次交接與走道事件。
- 現有 3–9 秒的操作成本維持原值，不因動畫額外扣時。
- 按鈕維持至少 44×44 CSS px。
- 首次點擊開始後才啟用音訊；不需要外部音檔或網路請求。
- 音效或本機儲存失敗時，遊戲仍可完成。
- 閱讀不計時；相機過渡不能推進遊戲時間。
- 遵守 `prefers-reduced-motion`，停用循環待機與鏡頭滑動。
- 不加入完整螢幕 AO 或景深後製，不更換引擎或第三方模型。
- 未完成或至少 2 次安全失誤為 0 星；練習不寫入正式最佳紀錄。
- GPU 畫面、可聽音效與效能必須分別驗證，不沿用舊版測試數字。
- 工作目錄是 `work/Cabingo`；所有下列路徑與命令以該目錄為根。

## Review Focus

1. 同一 seed 重玩仍是新一輪；音訊、動畫、最佳紀錄不可沿用上一輪的事件游標。由任務 1、3、6 測試。
2. AudioContext.resume() 非同步失敗、使用者在等待期間切換靜音或離開頁面，不得留下未處理例外或遲來聲音。由任務 3 測試。
3. 練習錯選保留同一 dialog，但每次明確選擇仍要觸發一次新反應；鍵盤長按不得連選。由任務 1、4、6 測試。
4. 未結束的處理遇上倒數歸零，不能提早完成任務或補播里程碑；由任務 1、4 測試。
5. 手機安全近景遇到滿櫃與對側空櫃時，必須保留判斷線索，標籤也不能遮擋選項。由任務 2、5、7 測試。

## Task 3：實作可降級的 Web Audio

**Files:** Create `public/audio.mjs`, `tests/audio.test.mjs`。

**Interfaces:**

```js
createCabinAudio({contextFactory, onUnavailable});
// -> {unlock, setPreferences, setMode, play, reset, dispose, getStatus}
// unlock(): Promise<boolean>，只能由使用者操作呼叫。
// setPreferences({muted:boolean, volume:number[0..1]}): void
// setMode('silent'|'reading'|'playing'|'paused'): void
// silent 關閉環境音、禁止新增事件但讓已播結算短音自然結束；
// paused 停止所有音源。dispose/reset 同樣清除所有音源。
// play({id:string, type:string, detail:object}): void
// reset(runId:string): void；清音源及去重紀錄，不重建 context。
// dispose(): void；冪等，取消排程，安全處理 close() 的 Promise。
// getStatus(): 'locked'|'ready'|'unavailable'|'disposed'
```

- [ ] 使用注入的 fake AudioContext 測試，確認 unlock 前不建立音源；重複 id 不重播；reset 後同名事件可播；pause 停止短音與環境音；最多八個短音同時播放。fake 實作 oscillator/buffer source/gain/filter 的 start、stop、connect、disconnect 與參數自動化記錄。
- [ ] 加入 resume 拒絕、建構拋錯、close 拒絕、等待 resume 期間 dispose／mute 的測試：

```js
let finishResume;
const contextFactory = () => fakeContext({resume: () =>
  new Promise(resolve => { finishResume = resolve; })});
const audio = createCabinAudio({contextFactory});
const unlocking = audio.unlock();
audio.dispose();
finishResume();
await unlocking;
assert.equal(audio.getStatus(), 'disposed');
assert.equal(fakeSourcesStartedAfterDispose(), 0);
```

- [ ] 執行 `node tests/audio.test.mjs` 確認缺少模組的失敗。
- [ ] 使用 gain 主通道，濾過噪音與低頻 oscillator 作環境音，簡短有包絡的雙音作鈴聲／介面音，短噪音作扣合與收合音。偏好設定由呼叫端傳入，模組不直接讀取 localStorage。
- [ ] 用事件 id 去重，限制集合大小 128。將 context 時間轉為即時播放，不依事件 elapsed 補播。短音淡出後 stop/disconnect；pause 與 dispose 立即移除待播音源，非同步完成回呼需檢查生命週期序號。

## 執行方式

建議由目前這個對話的同一位代理依序完成七項任務，再做一次獨立審查。事件、場景與控制器高度相依，這個方式較省協調成本。

另一個選項是每項任務交由新的子代理實作，再由另一位審查；隔離性較高，但每項都需重新載入上下文，成本較高。此選擇通過前不啟動子代理。
