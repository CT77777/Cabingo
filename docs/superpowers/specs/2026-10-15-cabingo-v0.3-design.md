# Cabingo v0.3 設計：讓第一章活起來

日期：2026-10-15
基準：v0.2.1，提交 `484aa96431e355e284bc12d6a0db93dc456306cf`
狀態：使用者已於 2026-10-15 確認功能範圍與本設計；尚未進入實作。

## 1. 目的與範圍

讓第一章的旅客、互動與回饋更有生命感，同時保留目前清楚的操作方向與流暢度。v0.3 採用現有 Three.js 與低多邊形美術，用程序動畫與合成音效改善演出。

這一版完成聲音、角色待機與反應、處理動作、安全判斷近景、頭頂圖示、交接提示、手機互動鈕、行李櫃比例，以及結算回饋。仍是一章、三項安全檢查、三個服務需求、一次交接與走道事件。正式模式維持 100 秒，練習模式維持不計時、不扣分。

第二章、旅客跨章記憶、解鎖與成就、完整配音、機外開場、Blender 模型流程和引擎遷移，列為後續工作。此版本不宣稱達到 3A 品質。

## 2. 現況與設計依據

- `preflight.mjs` 集中管理遊戲規則、倒數、選項、處理進度與結算。
- `scene.js` 使用真實 Three.js。旅客目前合併進靜態幾何批次，無法獨立轉頭或抬手。
- 場景已有行李升起、移入櫃內、關門和餐桌收合的動畫；缺少角色與道具之間的配合。
- `main.js` 管理輸入與介面；選項開啟時遊戲倒數暫停。目前相機也在這個狀態停止更新。
- 標籤主要投影在走道中央；旅客需求與實際座位缺少直接視覺連結。
- 交接選項目前已標出次數與 12 秒等待，但首次完整說明在交接完成後出現。
- 現有測試涵蓋規則、控制器、場景幾何與靜態版面。場景測試使用替代 renderer，不能代表實際 GPU 畫面或聲音品質。

## 3. 玩家體驗

### 3.1 聲音

首次點擊「正式巡艙」或「練習」時建立並啟用 Web Audio。開始畫面保持安靜。音訊無法啟動時，遊戲仍可完成，音效控制顯示不可用狀態。

加入以下合成聲音，無須外部音檔或網路請求：

| 聲音 | 觸發時機 | 要求 |
| --- | --- | --- |
| 機艙低鳴與空調 | 巡艙進行中 | 低音量、平滑淡入淡出；避免尖銳高頻 |
| 呼叫鈴 | 新服務需求出現 | 每個新需求只響一次；開局的服務需求也計入 |
| 選擇音 | 玩家成功送出選項 | 短促、輕量；被拒絕的重複輸入不發聲 |
| 修正音 | 選錯 | 與完成音有明顯區別；練習模式也提供反應 |
| 處理音 | 安全帶扣合、櫃門關閉、杯子交付、餐桌收起 | 與動作里程碑同步；暫停、恢復不重播已通過的里程碑 |
| 完成音 | 任務實際完成、同事送達 | 與「已安排交接」區分，避免誤認已送達 |
| 結算音 | 進入結算 | 依完成或需重試的狀態提供不同提示 |

介面提供靜音按鈕與 0–100% 主音量。偏好保存在本機；儲存失敗時仍可即時調整。靜音、音量為零或不支援音訊時，文字與視覺回饋保持完整。

暫停、失焦與頁面隱藏時停止環境音及事件播放；恢復後不補播過期音效。閱讀與首次說明時保留低音量環境音，暫停處理音。重新開始不留下舊聲音，離開頁面時釋放音訊資源。

### 3.2 旅客待機與反應

將旅客拆為身體、頭部、眼睛與手臂的可活動群組。保留共用幾何與材質，座椅與機艙仍使用靜態批次。

24 位旅客依座位分配三至四種低幅度待機：呼吸、看窗外、低頭閱讀或看手機、輕微調整坐姿。每人的相位不同。非任務旅客的待機道具不得看起來像待處理事件；任務旅客則維持與當前線索一致的姿勢。

開啟互動時，對應旅客看向組員。選錯時搖頭並調整眉眼；成功時點頭並露出微笑。練習模式可立即重選，新的反應取代舊反應，避免動畫堆疊。

走道事件中的站立旅客代表原本那位旅客：座位上的同一人暫時隱藏，返回座位後再顯示，避免同時出現兩個相同人物。

### 3.3 處理動作

處理動畫以現有 `action.time / action.duration` 決定進度。每次處理包含約 1–2 秒的主要手勢，其餘時間呈現協助、確認或等待。現有 3–9 秒的操作成本維持原值，不因動畫額外扣時。

| 情境 | 演出 |
| --- | --- |
| 收行李 | 組員轉向目標、彎身、抬手；行李沿既有路徑升起入櫃，最後櫃門關閉 |
| 已收好的行李 | 組員查看與確認；不得把已收好的行李拿出再收一次 |
| 收餐桌 | 旅客與組員配合伸手；有杯子與物品時先安置，再收合餐桌 |
| 已收好的餐桌 | 查看確認，保留已收妥狀態 |
| 安全帶 | 組員指示、旅客低頭伸手，扣合後顯示完整安全帶 |
| 已扣好的安全帶 | 查看確認，維持已扣合狀態 |
| 送水、送毯子 | 道具從組員手邊移向旅客；旅客伸手接取，完成後保留收到的道具 |
| 回答、交接、等候 | 組員轉向旅客、短促手勢，旅客給予回應；交接仍須等待同事實際送達 |

組員模型的朝向與手勢可調整，但遊戲碰撞位置維持原值。道具演出不能讓未完成任務提前取得完成狀態。處理中暫停與失焦，角色及道具停在同一進度。

完成時在對應旅客附近顯示短暫光環，搭配點頭與完成音。光環不遮擋線索，重開一輪會清除。

### 3.4 安全判斷鏡頭

開啟安全檢查時，相機約用 0.4 秒移到組員肩後，朝向對應旅客與安全線索。左右座位都必須能看見線索；行李情境需保留相關櫃子與行李的視野。近景按螢幕比例調整距離，避免手機過度裁切。

安全檢查選單放在畫面下方中央，內容可捲動，選項皆可點擊。近景期間隱藏待辦與不相關標籤，保留旅客與線索。關閉選單或選擇後平滑回到先前的巡艙／總覽鏡頭；鏡頭返回不增加額外的輸入鎖定時間。

快速服務維持玩家原本的鏡頭與選單流程。所有選單閱讀維持不計時。相機過渡使用獨立的視覺時間，不能推進需求耐心、處理進度或正式倒數。

### 3.5 頭頂圖示與辨識

安全檢查以驚嘆號表示；服務需求使用水杯、毯子、問號的 SVG 圖示，避免依賴手機 emoji 字型。圖示錨定對應旅客的頭頂，走道事件則錨定站立旅客。

遠處僅顯示圖示。只有進入互動範圍的當前目標展開完整短標籤，同時突出旅客輪廓附近的光環與相關物件。任務互動位置仍在走道，頭頂圖示不是新的碰撞或互動位置。

標籤先投影，再依當前目標與距離排序。保留當前目標，隱藏被介面遮住或與高優先圖示重疊的遠處圖示；不得把標籤推到別的旅客頭上。判斷面板只保留當前目標及必要的櫃位／資訊板細節。

主要介面改用任務名稱、前／中／後段及畫面左／右側辨識，不再依賴座位代碼。需要側向描述時，依相機投影判斷螢幕左右，不能直接把世界座標左側寫成畫面左側。內部仍保留座位代碼供資料與測試使用。

### 3.6 交接提示、手機按鈕與櫃子

第一次開啟含交接選項的服務面板，就在選項旁顯示：「每輪限 1 次。安排需 3 秒，同事再過 12 秒送達；服務回饋較少。」提示不得遮住選項，也不消耗交接額度。交接後不再用阻擋式首次說明打斷操作。

手機／觸控介面的互動鈕直接顯示「互動」，桌面保留 E 鍵提示。互動目標另以文字顯示。按鈕維持至少 44×44 CSS px，可透過鍵盤、觸控與輔助技術操作。

調整行李櫃的深度、門軸與開門角度，開門朝走道側，櫃門與箱體均留在機艙橫向範圍內。維持空櫃、滿櫃、其他空櫃與已收妥三種線索的可辨識性，並確認行李收妥後不穿出櫃體。

### 3.7 結算、星等與紀錄

結算先呈現結果與星等，再顯示一條可操作的建議，最後保留原有分數與時間明細。

| 條件 | 星等 | 評價限制 |
| --- | --- | --- |
| 完成回報、零安全失誤、零服務修正，服務分數至少 95 | 3 星 | 顯示零失誤完成 |
| 完成回報、零安全失誤，未達上述條件 | 2 星 | 指出服務或安排可改善處 |
| 完成回報、1 次安全失誤 | 1 星 | 保留「補救完成，紀錄保留」 |
| 未完成或至少 2 次安全失誤 | 0 星 | 保留未完成／需重試的評價 |
| 練習模式 | 不計星等 | 不寫入正式最佳紀錄 |

建議依序檢查：安全失誤、未完成項目／未回報、服務修正、服務逾時、零失誤挑戰。每輪只顯示一項最相關建議。

最佳紀錄保存在本機，按星等、較少安全失誤、較高服務分數、較短行動時間排序。相同表現不覆寫舊紀錄；資料無法解析、版本不符或儲存被拒絕時忽略該筆資料，遊戲仍正常結算。介面明示「此瀏覽器最佳紀錄」。

## 4. 模組與資料流

| 檔案 | 責任 |
| --- | --- |
| `preflight.mjs` | 維持規則權威；將交接說明移到選擇前；提供可辨識的演出事件 |
| `presentation.mjs`（新增） | 純函式：動作姿態、反應權重、近景姿態、標籤避讓、事件里程碑 |
| `audio.mjs`（新增） | Web Audio 生命週期、混音、音量與事件播放；失敗時降級 |
| `results.mjs`（新增） | 星等、建議、紀錄驗證與比較；與儲存機制分離 |
| `scene.js` | 角色可動群組、道具與光環、近景過渡、頭頂投影 |
| `main.js` | 連接規則與演出，設定聲音控制、更新介面、管理本機偏好與紀錄 |
| `index.html`、`style.css` | 音量控制、手機互動鈕、安全近景面板與結算版面 |

規則層提供有序號的短期事件：任務出現、決策錯誤、開始處理、任務完成、走道清除與結算。事件帶輪次、目標與必要動作資訊；佇列採固定上限。控制器按序號消費，音訊與場景各自記錄已處理的位置，避免每幀重播，也不因一個模組失敗而影響另一個。

處理音的中途里程碑由純函式判定進度是否跨越門檻。新一輪同時重設事件游標、角色反應、光環與里程碑。渲染函式不得直接改寫分數、任務、倒數或碰撞狀態。

## 5. 可及性、資源與效能

- 遵守 `prefers-reduced-motion`：停止循環待機、呼吸與眨眼演出，移除鏡頭滑動、搖晃與脈動，直接顯示當前必要姿態，保留靜態目標提示。
- 暫停、失焦與重新開始的輸入隔離維持原行為；打開音量控制時不把按鍵當成移動。
- 文字選單與觸控控制維持可見焦點；音量控制具名稱、目前值與靜音狀態。
- 共用幾何與材質，近景不增加像素比。不加入完整螢幕 AO 或景深後製；保留既有柔和陰影與色調映射。
- 音源設同時播放上限，使用短淡出避免爆音；每幀不新增 AudioContext，不無限累積節點。
- 場景與音訊在離開、重新建立與 WebGL 遺失時清理；重玩不累積事件或光環。

## 6. 驗收

| 編號 | 場景 | 可觀察的預期結果 |
| --- | --- | --- |
| A01 | 全新瀏覽器開啟、開始與重玩 | 開始前無聲；操作後有環境音；每輪各事件只播一次 |
| A02 | 靜音、音量零、儲存拒絕、Web Audio 不可用 | 設定可操作或清楚標示不可用；仍可完成一輪 |
| A03 | 暫停、失焦、隱藏頁面、恢復 | 規則與處理動畫凍結，音訊停止；恢復不補播舊事件 |
| A04 | 三種安全情境的所有線索變體 | 正確物件狀態、合理的手勢與道具移動；查看選項不重演收拾 |
| A05 | 送水、送毯子、交接送達、選錯與重選 | 接取與反應對應正確旅客，完成回饋不提前出現 |
| A06 | 左右座位與兩種巡艙鏡頭 | 安全判斷看得見旅客與關鍵線索；結束回到原鏡頭；閱讀不扣時 |
| A07 | 390×844 手機與桌面、多目標同時存在 | 圖示在對應頭頂，僅近目標展開；可見圖示彼此不重疊，避開 HUD |
| A08 | 第一次看見交接選項 | 選擇前可讀到限一次、3 秒安排與 12 秒送達，尚未消耗額度 |
| A09 | 觸控操作與櫃門開啟 | 互動鈕顯示文字，無字型方塊；櫃體及開門留在機艙內 |
| A10 | 完成、補救、重試、逾時與練習 | 星等符合表格；安全評價限制維持；練習不污染正式紀錄 |
| A11 | 減少動態效果與走道事件 | 無循環待機與鏡頭滑動；事件不產生座位／走道雙重旅客 |
| A12 | 多次重玩、關閉與 context lost | 無未處理例外、重複聲音、重複光環或殘留資源 |

先執行原有遊戲、輸入、場景與版面測試，再補事件去重、聲音生命週期、動畫暫停與里程碑、近景投影、標籤重疊、星等及紀錄容錯的回歸測試，並執行靜態建置。

瀏覽器人工檢查需包含桌面與 390×844 手機版、左右座位、至少一次正式完成與練習重選、音量操作，以及控制台錯誤。GPU 畫面與可聽音效品質需分別確認；自動化測試通過不代表已聽過聲音。若執行環境不支援其中一項，交付時列出尚未驗證的部分。

效能以相同裝置、相同場景比較修改前後幀時間與繪製呼叫；手機模擬需記錄 CPU 降速設定。穩定低於 30 fps 或持續比基準增加超過 25% 的中位幀時間，需減少動態陰影或待機更新成本後再驗證。不得沿用舊版 120 fps 紀錄宣稱新版本效能。
